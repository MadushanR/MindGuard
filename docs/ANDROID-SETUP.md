# Android development setup on Windows

Use a current Android Studio installation, JDK 17, an Android SDK compatible with Expo SDK 58 / React Native 0.88, and a running x86_64 emulator. Native folders are generated by Expo and ignored by Git; configure native behavior through app.json rather than editing generated code.

## Configure local paths

Set `JAVA_HOME` to JDK 17 and `ANDROID_HOME` to your SDK, or create the ignored `android.local.json` in the repository root:

```json
{
  "javaHome": "C:/path/to/jdk-17",
  "androidHome": "C:/path/to/Android/Sdk"
}
```

The Android runner also detects a JDK under `.tools/jdk17` and the normal `%LOCALAPPDATA%/Android/Sdk` location. It sets environment variables only for the build process, not system-wide.

The runner limits Gradle to two workers to reduce memory pressure on a 16 GB development machine. Set `maxWorkers` in `android.local.json` to override this locally.

## SDK and emulator

Use Android Studio's SDK Manager to install the platform/build tools requested by Expo, platform-tools, command-line tools, CMake 3.22.1, NDK 27.1.12297006, and an Android 36 Google APIs x86_64 system image. The SDK 37 base platform is currently named `platforms;android-37.0` in the SDK repository.

Create a Pixel 6 emulator named `MindGuard_API_36` through Device Manager. Enable hardware virtualization and the Windows Hypervisor Platform when required. Start the emulator before running the app. The project does not alter Windows virtualization features automatically.

If the connection service fails, run the SDK's `platform-tools/adb.exe start-server` from an ordinary terminal and inspect `adb devices`. A booted emulator should report `device`, rather than `offline`.

### Windows long-path fix

CMake 3.22.1 can ship Ninja 1.10.2, which fails when native source paths are long. Use Ninja 1.12 or newer. During this setup, Ninja 1.13.2 from the [official Ninja releases](https://github.com/ninja-build/ninja/releases) replaced the SDK's `cmake/3.22.1/bin/ninja.exe`; the original remains next to it as `ninja.exe.mindguard-backup`. No Windows registry setting was changed.

The launcher checks this tool version before a Windows build. See [Reanimated's Windows build guidance](https://docs.swmansion.com/react-native-reanimated/docs/guides/building-on-windows/). For another machine, also confirm Windows long-path support is enabled, or use the documented short-path workspace approach.

## Build and run

```sh
npm ci
npm run android
```

The first build downloads Gradle and native dependencies. If Metro is already running:

```sh
node scripts/android.mjs --no-bundler --device emulator-5554
```

The package ID is `com.mindguard.capstone`. The development build uses the same source and JSON fixtures as the browser preview. It explicitly blocks microphone permission because all voice behavior is simulated.

Use Explore to load scenarios and verify chat, voice states, local saving, and deletion. Stop and relaunch the application to verify persistence. Test keyboard visibility and composer position on the emulator; browser results do not establish native correctness.

Reference: [Expo local Android setup](https://docs.expo.dev/get-started/set-up-your-environment/?buildEnv=local&device=simulated&mode=development-build&platform=android).
